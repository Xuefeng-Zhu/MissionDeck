# Browser context implementation and privacy

The extension retains Mission Control's design and existing reviewed evidence flow. New optional permissions are `tabs` (picker metadata only) and HTTP/HTTPS host declarations (exact selected origins requested on a user click). Installation grants no new page hosts. Incognito is disabled. No history, cookies, debugger, interception, remote scripts, or page command bridge was added.

- Toolbar and selection context-menu invocation capture the original tab into the existing editable ten-minute inbox. Panel capture uses Chrome injection authorization, never assumes a visible panel grants a newly active tab.
- Choose tabs requests metadata on a gesture and displays it only locally. Capture selected once reads up to five authorized tabs, without switching/reloading discarded tabs. Readable structured text includes headings, lists, sanitized links, table cell positions, and visible status/alert text. Exclusion traversal omits forms, editable content, private-marked nodes, hidden/CSS-hidden content, scripts, and embedded frame content. Canvas/frame/unfinished pages are partial. Table header roles remain explicit; merged rows/columns are flagged as partial rather than invented. SVG content is excluded from both page and selection extraction. Literal formula-like text remains text; spreadsheet execution is the workspace adapter's separate responsibility.
- Live Assist is opt-in for the mission, exact origins and ten-minute worker-memory session. While the panel is mounted it polls at three-second intervals, coalesces overlapping polls, and shares only changed content hashes. The five-source limit includes the current foreground page; with five selected sources no additional foreground page is collected. Unselected prior foreground snapshots are removed. No model call is made merely because a DOM mutation occurred.
- Automatic sharing has its own unchecked consent box. Local extraction consent alone does not send content. Only explicitly authorized snapshots enter the backend context callback. Freeze strips browser IDs and bounds content to 50,000 characters. Backend request IDs are immutable. Model/provider retention cannot be recalled by local revocation.
- Pause, expiry, permission loss, mission switch, and panel cleanup invalidate pending results and clear temporary sources. Revocation clears conversation context synchronously; backend deletion waits for outstanding transmission so a delayed POST cannot follow its revocation DELETE. Each start renews session identity. A service-worker restart begins paused; browser restart does not resume consent. A crashed/unloaded panel cannot guarantee a network deletion finishes, so backend expiry remains necessary.
- Screenshots require a separate button, current page access, and before/after visible-tab/window/navigation checks. They stay in component memory for local preview, cropping, black-rectangle redaction or discard; keyboard users can redact the entire image. Keyboard-accessible numeric crop bounds are validated against the original image pixels. Image upload and vision inference are not implemented. Screenshot capture is never part of Live Assist.

## Verification and limits

Unit tests cover structured selection/table extraction, hidden/private exclusion, limits, navigation/permission epochs, session restart/expiry, frozen request immutability, source isolation and Chrome API identity/screenshot races. Chrome API mocks are contract tests, not native side-panel proof. Native toolbar/context-menu gesture behavior, real host grants, and multi-window screenshot timing still require browser/manual verification. Polling is intentionally panel-bound rather than persistent background automation; no long-running mission depends on it. Stored approved mission evidence uses the existing retention/deletion flow; pausing temporary context never deletes approved artifacts.

Official Chrome references checked September 12, 2026: [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [sidePanel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel). Optional hosts are declarations rather than grants; permissions.request must be invoked from a user gesture; tabs metadata does not authorize DOM injection.
